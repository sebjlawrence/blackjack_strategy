# Monte Carlo Blackjack Strategy Optimiser

> **Disclaimer:** This README was generated by AI (Claude, by Anthropic) based on the project's code and results. It has been reviewed by the author, but please refer to the source code as the definitive description of how the project works.

A Python blackjack simulator that derives an optimal playing strategy from first principles using Monte Carlo simulation, then evaluates it against simpler strategies with proper statistical confidence intervals.

The derived strategy was built purely by simulation, with no published strategy chart as input. It matches published basic strategy on **98% of decisions** and performs within statistical error of the theoretical optimum.

## Results

Each strategy was played for 1,000,000 rounds using the same sequence of shuffles.

| Strategy | Mean return per hand | 95% confidence interval | Std dev |
|---|---|---|---|
| Always hit | −88.47% | −88.51% to −88.42% | 0.521 |
| Always stand | −15.74% | −15.83% to −15.65% | 0.992 |
| Mimic the dealer | −5.85% | −5.94% to −5.76% | 0.978 |
| Up-card heuristic | −3.53% | −3.62% to −3.45% | 0.985 |
| **Derived basic strategy** | **−0.69%** | **−0.79% to −0.59%** | **1.152** |

None of the confidence intervals overlap, so each step up the ladder is a statistically significant improvement:

- **Mimic the dealer** shows where the house edge comes from. Player and dealer play identically, but the player acts first and loses whenever they bust, even if the dealer would also have busted.
- **The up-card heuristic** (stand on 12+ against a dealer 2–6, otherwise hit to 17) shows that using the dealer's visible card is worth about 2.3%.
- **The derived strategy** adds doubling, splitting and soft-hand play, worth a further 2.8%. Its result is consistent with the published house edge of roughly 0.6–0.65% for these rules.

## How it works

### Game engine

`game_engine.py` models the game:

- **`Shoe`** builds and shuffles a multi-deck shoe, deals cards, and reshuffles once 75% has been dealt.
- **`Hand`** holds a hand's cards and calculates its total, whether it is soft (an ace counted as 11), bust, or a blackjack.
- **`play_hand`** plays a single hand by repeatedly asking a strategy for a decision. Splitting is handled **recursively**: a split hand calls `play_hand` on each of its two new hands, so resplits work automatically. It returns a list of results, one per final hand.
- **`settle`** plays the dealer once (only if at least one player hand is still live) and scores every hand.
- **`play_round`** plays a full round from a random deal; **`play_from_position`** plays from a chosen player hand and dealer up-card.

Strategies are plain functions that take the player's hand and the dealer's up-card and return `'hit'`, `'stand'`, `'double'` or `'split'`. The engine carries out the decision and raises an error if it is illegal, so strategies can be swapped without touching the game code.

### Deriving the strategy

`derive_table.py` builds the strategy table by simulation. For every situation (a player hand against a dealer up-card), it:

1. forces each possible first action (hit, stand, double, and split for pairs)
2. plays the rest of the hand using the table built so far
3. averages the result over N rounds, and stores the average for each action

Two techniques make this work:

- **Dependency ordering.** Each entry relies on later decisions already being in the table, so sections are filled in a specific order: hard 20 down to 12 (hitting these only reaches higher hard totals), then soft hands, then hard 11 down to 5 (which can become soft by drawing an ace), then pairs. Pairs are filled twice, so that resplit decisions on the second pass use the first pass's answers.
- **Common random numbers.** Round *i* uses the same seeded shuffle for every action being compared, so the difference between two actions comes from the decision rather than from luck. This greatly reduces the number of rounds needed to separate close decisions.

### Evaluation

`simulations.py` plays each strategy for a large number of rounds and reports the mean return, standard deviation and a 95% confidence interval (mean ± 1.96 × standard deviation ÷ √N). Running totals of the results and their squares are used instead of storing every result, so memory use stays constant however large N is.

## Rules simulated

- 6-deck shoe, reshuffled after 75% penetration
- Dealer hits soft 17 (H17)
- Blackjack pays 3:2
- Doubling allowed on any first two cards, including after a split (DAS)
- Splitting up to 4 hands; split aces receive one card each and cannot be resplit
- A 21 made after a split is not a blackjack
- No surrender or insurance
- The player only makes decisions when the dealer does not have blackjack

## Project structure

| File | Purpose |
|---|---|
| `game_engine.py` | Shoe, hands, dealer play, round logic and settlement |
| `strategies.py` | Baseline strategies, the table-based strategy, and helpers for loading tables |
| `derive_table.py` | Derives the strategy table by Monte Carlo simulation |
| `simulations.py` | Compares strategies with confidence intervals |
| `basic_strategy_N=*.json` | Derived strategy tables, storing the expected value of every action in every situation |

## Usage

Requires Python 3. Only the standard library is used.

Derive a strategy table (set `N` at the top of the file; run time scales directly with N):

```
python derive_table.py
```

Compare strategies:

```
python simulations.py
```

## Limitations

- **Representative hands.** Each table entry is computed from one example hand (for instance, hard 16 as 10 + 6). Hands with the same total but different cards behave very slightly differently, because of which cards remain in the shoe. Published basic strategy makes the same simplification.
- **Shared seeds.** Every situation uses the same set of seeded shuffles, so any quirk in that set affects the whole table in the same way. Rerunning with a different seed is a useful check on the near-tied decisions.
- **Split limit.** Resplitting is limited by depth rather than by an exact count of hands, which is nearly equivalent in practice.
- **Chosen cards are not removed from the shoe** when playing from a fixed position, which has a negligible effect with 6 decks.

## Possible extensions

- Card counting (Hi-Lo) with bet sizing based on the true count
- Configurable rules (S17, no DAS, surrender) to measure what each rule is worth
- Reinforcement learning (e.g. Q-learning) as an alternative way of deriving the table
- Composition-dependent strategy, using the exact cards in a hand rather than just the total
